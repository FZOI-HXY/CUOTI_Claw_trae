# 项目约束（Project Rules）

> 本文件为 TraeCode 项目级规则，约束所有后续会话与子代理在该仓库中的工作方式。
> 规则按优先级排列，冲突时以序号小者为准。

## 1. 多子代理（多发子代理）— 强制

- **QA / 测试 / 审查类任务必须并发派发多个子代理**（`Task` 工具，`subagent_type` 视任务而定），禁止单次只用一个串行执行。
- 典型场景（不限于）：
  - 全量回归测试 → 至少按模块/语言栈拆分并发跑（如 Python、Rust core、前端 分开并行）。
  - 安全审查 → 与功能测试并行派发。
  - 代码 review → 与测试并行派发。
- 派发时在**同一条消息里并行发起多个 `Task` 调用**，不要逐个等待。
- 每个子代理给出**独立结论 + 可复现的命令/路径**；主代理汇总冲突项并统一裁决。
- 目的：缩短周期、交叉验证、减少单点遗漏。除非用户明确要求单线程，否则默认发多子代理。

## 2. 变更范围最小化

- 只做被要求的事，不顺手重构、不新增无关文件。
- 优先编辑已有文件；确需新建时先说明理由。
- 不主动创建文档（*.md）除非用户明确要求。

## 3. 测试与验证纪律

- 改 Rust：跑 `cargo test -p cuoti-core`（全 workspace 因沙箱缺 glib 可能失败，以 `cuoti-core` 为准）。
- 改 Python：跑 `/workspace/tests` 下对应 pytest。
- 改前端：跑 `tauri/frontend` 的 vitest。
- 提交前必须跑对应回归，确认无回归。

## 4. 提交纪律

- 未经用户明确要求，不主动 `git commit` / `git push`。
- 提交时按模块分文件 `git add`，消息用常规约定（feat/fix/test/chore + 中文说明）。

## 5. RAG 约束（延续既有设计）

- 不新增第三方依赖；`retrieve` 签名与 `RagSource` 结构不变；前端零改动。
- 混合检索（hybrid.rs：BM25 + RRF）为核心，后续优化需保持接口稳定。
