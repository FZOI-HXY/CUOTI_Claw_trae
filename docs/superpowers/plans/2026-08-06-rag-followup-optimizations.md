## 联网调研：2026 RAG 架构全景与选型依据

> 结论节选自 IBM/arXiv RAG Stack 综述、USTC 大规模 RAG 缩放对比研究、及多篇 2026 生产环境工程指南。

### 1. RAG 架构演进五代

| 架构 | 核心机制 | 质量 | 成本/查询 | 适用场景 |
|------|---------|------|-----------|----------|
| Naive RAG | 向量检索 + 直接生成 | 基线 | $0.001 | 简单单跳 QA（已基本淘汰） |
| Advanced RAG | 混合检索(BM25+向量) + 重排 + 查询改写 | 高 | $0.005 | 生产基线，性价比之王 |
| Modular RAG | 检索器/生成器/编排器解耦组合 | 高 | $0.01-0.05 | 多域企业 |
| Graph RAG | 知识图谱 + 图遍历 + 社区摘要 | 关系推理最高 | $0.02-0.15 | 跨文档/多跳/全局总结 |
| Agentic RAG | Agent 自主多轮检索 + 自纠正 | 最高 | $0.01-0.10 | 多跳复杂推理 |

### 2. 关键结论（对当前项目最相关）

1. **检索是瓶颈，不是生成。** RAG 失败约 73% 在检索环节，非生成；Naive RAG 约 40% 检索失败。→ 印证本项目把优化集中在 `retrieve` 的方向正确。
2. **重排(Rerank)被多篇称为"10x 质量放大器"**：cross-encoder 对 top-k 精排，是仅次于检索的最有效优化。→ 对应 Group 2 第 6 项。
3. **BM25 被大规模对比研究验证为成本-精度最优**：中大规模语料下 BM25 精度领先且无需 LLM 建索引；Graph RAG 有"构建墙"（建图成本极高）；纯文件 Agent 查询 token 是 BM25 的 39 倍。**Agent + BM25 组合（69.4 分）远超纯 Agent（36.9）。** → 强烈支持本项目"BM25+向量+RRF 混合"的既有设计。
4. **Adaptive RAG / HyDE / Self-RAG / FLARE** 是检索优化主流方向，均已在 Group 3 覆盖。
5. **Parent-Document 多向量检索**：检索小 chunk、喂大上下文，缓解切块割裂问题。
6. **缺评估 = 短板**：生产级 RAG 普遍用 RAGAS/命中率/引用率量化检索与生成质量；当前项目无评估环节。

### 3. 对项目选型的启示（更新）

- 现有 **BM25 + 向量 + RRF** 设计已被规模研究验证为高性价比，**无需推翻**。
- 下一步性价比最高：**cross-encoder 重排**（Group 2 第 6 项）——需新增依赖，按规则5评估。
- **Adaptive 路由**（Group 3 第 10 项）可动态省成本，适合后续。
- 建议补一个**最小化评估**（检索命中率、回答是否引用题目原文），否则难以量化优化收益。
